# Doc-Ray 1.52.0

Version 1.52.0 answers a question the corpus used to refuse: **how common is this
phrase?**

## Who is affected

- **Anyone checking a term before searching** — asking about a multi-word phrase
  now returns a number instead of "cannot say".
- **Integrators and agents** using `termFrequency` / `term_frequency`. Existing
  single-word calls are unchanged; four new fields appear on every result.

## What changed

Before searching, you can ask how common a term is, so you can pick one that
won't flood the results. For a single word that has always worked. For a phrase —
"Model Context Protocol", "shared_buffers", "COVID-19" — the answer was an
estimate built from the individual words, which could not tell you whether the
words ever appear *together*. In practice that meant running the search anyway,
which is the cost the check exists to avoid.

Now a phrase is **measured**: the server counts the passages that actually contain
it, using the very same matching rule the search itself uses. So the check now
predicts the search rather than approximating it, and it can tell you plainly
whether the phrase occurs at all.

## What to know before relying on it

- **A "capped" count is a floor, not a total.** Counting stops once a phrase is
  clearly too common to search usefully. When that happens the result says so, and
  the number means *at least* that many. Never read it as an exact total.
- **The verdict bands are about readability, not rarity.** "Low" means the matches
  fit in a single page of results; "moderate" means more than a page, so a search
  will hit its limit; "high" means it floods, and you should narrow the phrase or
  read a section directly instead.
- **A zero is now a real answer.** If a phrase does not occur, you are told that it
  was searched and not found. That is absence of the exact string — not absence of
  the idea, so a different spelling or a shorter fragment may still find it.
- **Single words are unchanged.** Same numbers, same thresholds. Results now carry
  a label saying which method produced them, so you can tell the two apart.

## Action required

None. This release adds a database column and changes no existing data. Callers
reading only the previously existing fields are unaffected; the new fields are
additive.
