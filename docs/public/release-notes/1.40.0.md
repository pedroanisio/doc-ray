# Release notes 1.40.0

What changed in version 1.40.0, who it affects, and any action required.

## Fixed

### Editing a document's authors now saves

Updating a document's authors could fail and leave the change unsaved. Author edits
now save correctly, alongside the other editable metadata, and are covered by
regression tests.

**Who it affects.** Anyone who edits document metadata through the Corpus browser,
the GraphQL API, or the MCP server.

**Action required.** None. Re-apply any author edit that did not save previously; it
now persists.

See [How-To: Edit document metadata](../how-to/edit-document-metadata.md).

### Automatic backups capture the full corpus

An automatic backup could fail partway through and leave no usable snapshot. Backups
now capture the full corpus reliably. A backup that cannot read everything it needs
stops and names what it could not read, rather than writing an incomplete archive —
an incomplete backup is treated as data loss on restore, never as a silent skip.

**Who it affects.** Administrators responsible for backups and recovery.

**Action required.** None. Confirm recent backups are completing as expected.

See [Concept: Backups](../concepts/backups.md) and
[How-To: Create a backup](../how-to/back-up-and-restore.md).
