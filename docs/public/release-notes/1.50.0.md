# Doc-Ray 1.50.0

Version 1.50.0 introduces explainable confidence-guided review for named-entity
mentions. Reviewers can begin with the mentions most likely to need correction
instead of reading the entire corpus in arbitrary order. It also removes a
connection-setup penalty from sequential MCP workflows and compresses large JSON
responses without buffering event streams.
Agent clients also receive a human title and complete behavioral hints for every
MCP tool, so they can distinguish reads, destructive writes, repeat-safe calls,
and operations whose queued work reaches an external source.
The evaluation baseline now accounts for this up-front discovery cost rather
than measuring only responses after a task begins.

## Who is affected

- **Curators and agents** can retrieve a document's least-confident entity
  mentions first and see why each mention was flagged.
- **Integrators** receive a nullable confidence value, its producing method, and
  human-readable reasons on the review surface.
- **Administrators** gain a worker job that materializes the ranking after
  annotation without slowing the annotation model itself.
- **MCP operators** gain a shared, bounded GraphQL connection pool and scoped
  response compression. Caller credentials remain isolated per request.
- **MCP clients** can use the 64 tools' advertised titles and all four standard
  behavior hints when presenting or planning actions.
- **Maintainers** gain a regression guard for `tools/list` growth in both the
  default read-only registry and the opt-in write registry.

## What to know before relying on it

- The initial method is `heuristic:v1`. It combines measured type disagreement,
  canonical-registry novelty, corpus rarity, and span-shape anomalies.
- The score is a review-ordering signal, not a calibrated probability. Reasons
  must be displayed beside it.
- Existing mentions remain valid with no score until the scoring job runs.
- A mention already covered by a durable human correction is omitted from the
  uncertain review list.
- The MCP pool defaults to 100 total connections and 20 idle keep-alive
  connections. JSON bodies of at least 1 KiB can be gzip-compressed;
  `text/event-stream` responses are never compressed.
- Tool hints are advisory, not authorization. Four queued writes are marked
  open-world because they can reach arXiv, a configured frontier resolver, or
  Wikipedia/Wikidata; GraphQL scope, billing, ACLs, and RLS still decide access.

## Action required

Apply migrations 138 and 139, then run the mention-scoring job for documents
whose existing mentions should appear in the review queue. Newly annotated
documents are scored automatically. The MCP pool defaults require no change;
set `DOCRAY_MCP_POOL_MAX_CONNECTIONS` or
`DOCRAY_MCP_POOL_MAX_KEEPALIVE` only when deployment capacity calls for it.
Tool metadata requires no operator configuration.
The evaluation guard defaults to 5% allowed discovery-payload growth; use
`--surface-tolerance` only when comparing or deliberately refreshing a baseline.
