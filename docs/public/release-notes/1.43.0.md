# Doc-Ray 1.43.0

Version 1.43.0 completes the webapp experience epic (#23): semantic and visual
discovery, human review, Lens controls, and cited briefings now have aligned
human, GraphQL, application, and MCP paths.

## What users can do now

- Search `/search` by literal keyword, learned Sentence meaning, or image
  meaning, with explicit fallback and coverage states.
- Review metadata suggestions, Entity corrections/seeds, and untrusted visual
  captions from `/review`; visual decisions are attributable and audited.
- Promote Collections to Lenses and set a member Document's default Lens from
  the webapp, while the database continues to enforce Lens invariants.
- Inspect actual Document image bytes, Tier-1 coverage, classes, committed
  captions, and cross-modal results without bypassing RLS.
- Build a deterministic, gap-honest cited evidence pack at `/briefing` or with
  GraphQL `briefingPack` / MCP `briefing_pack`.

## API and MCP additions

- GraphQL reads: `briefingPack` and `visualReview`; existing
  `semanticSearchSentences`, `documentImages`, `imageClassSummary`,
  `visualCaptions`, and `crossModalImageSearch` now have complete webapp paths.
- GraphQL writes: `decideVisualCaptions`, `embedDocumentSentences`, and
  `embedCorpusSentences`.
- MCP: `visual_review` plus the existing semantic, visual, briefing, Lens, and
  correction tools are included in the documented inventory. Write tools still
  require `DOCRAY_MCP_ENABLE_WRITE=true` and API authorization.
- Doc-Ray publishes no client SDK in this release. There is therefore no SDK
  package to upgrade; integrations use the GraphQL contract or MCP server.

## Operator action required

1. Apply migrations through the normal deployment path. Marker migration
   `125_schema_version_1_43_0.sql` advances the global package/schema contract;
   it contains no structural DDL.
2. Confirm the API reports `version: 1.43.0` and
   `docray_schema_version()` returns `1.43.0`.
3. If the learned-model cutover has not covered the corpus, follow the
   [Corpus Embedding Backfill Runbook](../../runbook-corpus-embeddings.md).
   Back up first, enqueue only missing Documents, and verify sentence/model
   counts before enabling Meaning search for users.
4. The semantic job is routed to the heavy worker lane. Its optional Compose
   timeout is `WORKER_JOB_TIMEOUT_SEMANTIC_EMBED_SECONDS` (default: 14,400
   seconds).
5. Tier-2 visual jobs use bounded image/text encoder calls. The default
   `DOCRAY_VISION_BATCH_SIZE=16` is suitable for ordinary GPU workers; lower it
   and restart the worker before retrying a failed job if device memory is more
   constrained. The setting must be a positive integer.

## Compatibility and migration guidance

- This is an additive API release over the 1.42.0 learned-embedding cutover.
  No existing field is removed.
- Tier-3 caption proposals remain untrusted. Consumers that previously read
  `visualCaptions` continue to receive committed captions only; use
  `visualReview` for the decision queue.
- Briefing composition in 1.43.0 is lexical/keyword based. Semantic briefing
  retrieval is intentionally a follow-up, not implied by this release.
- A strict offline parity gate now fails when a GraphQL root field has neither
  a webapp binding nor a reasoned API-only classification.
- Existing Tier-2 rows require no migration. A failed pre-1.43 visual job can be
  retried safely because each Document/model replacement remains atomic and
  idempotent.

## Rollback

Application rollback is safe because migration 125 adds no schema structure.
Keep package and schema versions in lockstep: roll back the application and
restore the pre-deploy database backup rather than manually rewriting
`schema_version`. Learned embeddings remain governed by the 1.42.0 cutover
runbook.
