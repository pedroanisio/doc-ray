# Doc-Ray 1.51.0

Version 1.51.0 adds durable, exact-surface NER correction rules and an explicit
phrase mode for Document-level full-text search. A systematic model error can
be recorded once per target document and will keep applying to matching mentions
produced by future annotation runs.

## What to know

- Matching is exact and case-sensitive on both the stored surface and its
  current entity type.
- Surface rules and single-span corrections share one chronological log; the
  later decision wins when both affect the same mention.
- The database stores `NULL` span coordinates for a surface rule rather than a
  fabricated sentinel.
- `entitySurfaceOccurrences` previews exact matches in an explicit, bounded
  Document list. Its count cap and truncation flag are part of the response.
- `correctEntitySurface` records the same rule in each authorized Document and
  enqueues one `apply_corrections` Job per Document.
- The MCP `correct_entity_surface` tool defaults to preview-only
  (`dry_run=True`). Applying the rule requires `dry_run=False`; collection scope
  is refused when a 200-member page cannot prove complete membership.
- `fullTextSearch(mode: PHRASE)` and MCP `full_text_search(mode="phrase")`
  require normalized search terms in order. The historical all-term behavior
  remains the default (`TERMS`/`"terms"`). Both modes use the Document's language
  configuration; neither accepts raw Postgres query syntax.
- `termFrequency` and MCP `term_frequency` accept whitespace phrases. Their
  `measurement` is `component_upper_bound`: `uses` is the rarest component's
  count, not a claim that those words are adjacent. Confirm actual matches with
  phrase-mode full-text search.
- MCP Streamable HTTP is stateless. Initialization and later calls may land on
  different processes or span a restart; no sticky routing or shared MCP session
  store is required. Each request still presents and validates its bearer token.

## Interfaces

- GraphQL query: `entitySurfaceOccurrences(documentIds:, surface:, originalType:, sampleLimit:, countCap:)`
- GraphQL mutation: `correctEntitySurface(documentIds:, surface:, originalType:, action:, entityType:, rationale:)`
- MCP write tool: `correct_entity_surface(surface, original_type, action, document_id?, collection_id?, entity_type?, rationale?, dry_run=True)`
- Durable actions: `reclassify_surface` and `reject_surface`
- GraphQL query: `fullTextSearch(query:, limit:, mode:)`
- MCP read tool: `full_text_search(query, limit=25, mode="terms")`
- GraphQL query: `termFrequency(terms:)` (`measurement` is `exact`,
  `component_upper_bound`, or `unavailable`)
- MCP transport: stateless Streamable HTTP at `/mcp`

## Action required

Apply migrations 140 and 141 before using the new correction actions. Existing
span corrections and their readback remain compatible; their `charStart` and
`charEnd` fields are now nullable only because surface rules carry no span.
