# Doc-Ray 1.57.2

Library-wide statistics track the library again.

## Who is affected

- **Anyone reading corpus totals** — document, sentence, lexeme and occurrence
  counts. Since the previous release these stopped advancing as documents were
  added, so a growing library kept reporting the totals it held when the fault
  began.
- **Anyone checking how common a term is** before searching. That verdict divides
  a term's count by a library-wide total, and the total had stopped being updated,
  so the resulting share — and the crowded-or-rare judgement built on it — drifted
  further from reality with every document added.
- **Administrators upgrading an existing installation.** One command is needed
  after the upgrade; see below.

Retrieval itself was never affected. Search, reading, citations and entity results
stayed correct throughout. The fault was confined to the maintained summary
figures *about* the library.

## What changed

**Per-document statistics are being recorded again.** Doc-Ray keeps a running
summary of each document's vocabulary and entity counts and rolls those up into
the library-wide totals. Recording that summary required a database permission the
component doing the recording had never been granted, so every attempt failed from
the moment the incremental summary path was introduced.

The failure was reported rather than raised: ingestion continued normally, logged
a warning for each document, and left the summaries untouched. Nothing broke
loudly, which is how a library could take in hundreds of documents while its
reported totals stood still.

**The affected figures** are the corpus totals for sentences, lexemes and
occurrences, the per-document vocabulary and entity summaries beneath them, and
the library-wide total that term-frequency shares are measured against. Where a
total could not be established, Doc-Ray already declined to invent one — a share
it could not compute honestly was reported as unavailable rather than as a number.

**A safeguard now covers the whole class of fault.** The build checks that no
internal routine can name a helper it is not permitted to run, so an omission of
this kind fails during development instead of in a running system.

## Action required

**Administrators: run one refresh after upgrading.** Apply the database migrations
shipped with this release as usual, then run:

```sql
SELECT docray_refresh_all_corpus_stats();
```

This rebuilds every summary from the current contents of the library and clears
the drift accumulated while the fault was present. Expect it to cost roughly one
full refresh cycle for your library; it reads and rewrites summary figures only,
and touches no document content.

Until that refresh runs, corpus totals keep reporting their stale values. No
document needs re-ingesting, re-annotating or re-indexing, and no client or
integration needs updating.
