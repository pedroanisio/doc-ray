# Doc-Ray 1.57.4

Library-wide statistics follow the library again, and this time the fault could
not have announced itself.

## Who is affected

- **Anyone reading corpus totals or per-term frequencies.** Since 1.57.2, the
  running totals behind the corpus overview, the term-frequency check and the
  share figures that search verdicts rely on stopped advancing as documents were
  added and analysed, while their "last computed" time kept updating. A growing
  library reported the numbers it held when the fault began, and nothing looked
  stale.
- **Administrators.** One migration, applied as usual, repairs the mechanism and
  recomputes the figures. No further action is needed.

Search results, document text, citations and entity results were never affected:
only the aggregate counts derived from them lagged.

## What changed

**The maintenance step that keeps the totals current now runs with the access
it needs.** After each document is analysed, a small database routine compares
that document's words and entities with the previous snapshot and adjusts the
library-wide counts by the difference. That routine had been created without
naming the account it should run as, so it ran as an ordinary account whose
view of the library is limited by the access rules. From that vantage point it
saw no rows for the document, concluded the document contributed nothing, and
adjusted nothing — a result indistinguishable from "already up to date", so no
error was raised and the overview's timestamp was refreshed as though the work
had been done.

The routine is now explicitly assigned to the maintenance account that the
access rules do not limit, the migration refuses to complete if that assignment
did not take, and every library's counts are rebuilt once from the analysed
documents themselves, because the missed adjustments cannot be replayed.

**A new check prevents the same omission at authoring time.** Any maintenance
routine of this kind added in the future must state its owning account in the
migration that creates it, or the test suite fails before the change can ship.

## Action required

Apply the database migrations shipped with this release as usual. The rebuild of
the counts runs as part of the migration; on a large library it can take a few
minutes. No document needs re-uploading or re-analysing, and no client or
integration needs updating.
