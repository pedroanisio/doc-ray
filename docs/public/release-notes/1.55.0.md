# Doc-Ray 1.55.0

Image descriptions now appear on documents as soon as they are generated, marked
as machine proposals, and anyone reading a document can withdraw one that is
wrong.

## Who is affected

- **Everyone reading documents.** Images that had no description now show one,
  labelled with the model that wrote it and how well the surrounding text
  supports it.
- **Anyone who reviewed image descriptions.** The review queue is no longer how
  descriptions become visible. It remains available for deployments that choose
  to hold weaker descriptions back.
- **Administrators.** One new setting, and a database migration.

## What to know

Image descriptions used to be withheld until a person approved each one. In
practice almost none were: descriptions had been generated for thousands of
images and only a couple of dozen were ever approved, because approving them one
at a time was not work anyone could finish. The effect was that images across the
whole library stayed undescribed.

Descriptions are now published when they are generated, and withdrawn when they
turn out to be wrong. Three things keep that honest:

- **A description is never presented as the library's own statement.** It is
  labelled as a model proposal and shown with a percentage indicating how much of
  it the document's own text supports. A low percentage is a reason to read it
  sceptically — though it can also simply mean the page around the image has
  little text to compare against.
- **Anyone reading a document can withdraw a description.** Each described image
  offers a *Retract this caption* control that asks why. A withdrawn description
  leaves the document immediately.
- **Every withdrawal is recorded** — who withdrew it, when, and the reason given.
  Nothing is erased, so a pattern of poor descriptions stays visible.

Text that is not a usable description at all — empty, or fragments of the model's
own internal output — is still discarded automatically and never appears.

## Action required

**Administrators must apply the database migration** before deploying this
version. No configuration change is required.

To hold weaker descriptions back from documents, set
`DOCRAY_CAPTION_APPROVE_FLOOR` to a value between `0` and `1`. Descriptions
scoring below it go to the review queue instead of appearing on the document. The
default is `0`, which publishes everything usable. Setting it to `1` reproduces
the previous behaviour, where every description waits for approval.

Integrators can withdraw a description through the API with
`retractVisualCaption(captionId, reason)`, or through the agent interface with the
`retract_visual_caption` tool. Both require a reason, and both report how many
descriptions were withdrawn — so a call that matched nothing is distinguishable
from one that succeeded.
