# Doc-Ray 1.56.0

Term-frequency lookups work again, and a document can no longer be left
half-processed by a passing hardware shortage.

## Who is affected

- **Anyone who checks how common a word is before searching.** Term-frequency
  lookups were timing out and returning nothing — even for single ordinary
  words. They now return promptly. Nothing about the numbers changed; only the
  time taken to produce them.
- **Anyone whose documents were uploaded in a large batch.** A document could
  previously stop partway through processing and stay that way, with no
  indication that it had stopped rather than merely been queued. That no longer
  happens, and any document already in that state is now reported.

## What changed

**Term-frequency lookups no longer time out.** The share each term represents
was recalculated across the whole corpus on every request, which grew slower as
the corpus grew until requests exceeded their time limit and failed outright.
The figure is now maintained as the corpus changes and simply read back.

**Processing survives a busy moment.** When the machinery a document needs is
momentarily oversubscribed, processing now waits and tries again over the
following hour instead of giving up within seconds. Previously a brief shortage
could exhaust every attempt before it had passed, and because the first stage
feeds all the others, the document would quietly stop there — no analysis, no
search indexing, no image work — with nothing to resume it.

A genuine fault, as opposed to a busy resource, is still reported quickly rather
than being retried for an hour to no purpose.

**Stopped documents are now visible.** A document whose processing has stopped
for good is reported as an error naming the stage that stopped, instead of being
described the same way as one still waiting its turn.

## Action required

None for most people.

If you administer an installation, the health report may now list documents that
had already stopped before this release. They were always in that state; it was
not previously distinguishable from work still pending. Re-running the named
stage clears each one.
