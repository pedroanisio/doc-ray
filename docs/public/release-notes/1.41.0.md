# Release notes 1.41.0

What changed in version 1.41.0, who it affects, and any action required.

## Added

### Lenses — name a scope by promoting a collection

Promote a Collection into a named Lens to define a scope over your Corpus. A Lens is
metadata only in this release: naming a scope does not change how entities resolve
today. Every existing read returns the same entities and the same results whether or
not a lens exists. A lens establishes the vocabulary for scoped resolution in a
later release.

The reserved Global lens holds identities shared across the whole corpus and cannot
be renamed, demoted, or deleted.

**Who it affects.** Curators who organize a corpus, and integrators building on the
GraphQL API or the MCP server. Promoting and demoting a lens are write actions; over
the MCP server they require the write gate.

**Action required.** None. Adopting lenses is optional, and existing corpora are
unchanged.

See [Concept: Lenses](../concepts/lenses.md) and
[How-To: Promote a collection to a lens](../how-to/organize-with-lenses.md).

## Fixed

### Entity dossiers over MCP report honest totals

The entity dossier tool on the MCP server could report the passages it returned as
if they were an entity's complete total, understating how many documents mention the
entity and, in some cases, presenting a partial answer as a complete one. The tool
now separates the passages it cites from the totals, reports how many documents
mention the entity, and flags when a result is truncated, so an agent can tell a
complete answer from a capped one.

**Who it affects.** Integrators whose agents call the entity dossier tool.

**Action required.** None. Agents that read the reported truncation and document
count get more accurate answers automatically.

See [Reference: MCP server](../reference/mcp.md).
