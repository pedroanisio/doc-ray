# Doc-Ray 1.48.2

Version 1.48.2 lets documents come from somewhere other than your filesystem,
and makes bulk loading tell the truth about what it did.

## Who is affected

- **Readers and researchers** — you can now ingest a paper by reference instead
  of downloading it first. arXiv is the first supported source: an `abs` or
  `pdf` URL, `arxiv:<id>`, or a bare identifier. The paper's real title comes
  from arXiv itself, falling back to the title read out of the file if that
  lookup fails.
- **Administrators running bulk loads** — the loader that fills a corpus from
  object storage no longer wastes bandwidth re-fetching documents it can never
  read, and no longer reports those documents as though they were fine.

## What to know before relying on it

- **A document that cannot be read stays unreadable, and now says so.** Files
  with no extractable text — typically scanned PDFs with no text layer — are
  recorded as failed. Re-running the loader used to re-download each one and
  then report it as an already-present duplicate, so a load could finish
  "clean" while leaving failed documents behind. Those documents are now
  reported as failed every time they are encountered. The remedy is unchanged:
  run OCR on the file. Doing so changes the file, which is what lets the loader
  pick it up again.
- **Newly loaded documents report accurate counts immediately.** Documents
  loaded in bulk could show zero sentences until unrelated later work happened
  to correct the figure — and would stay wrong indefinitely if post-processing
  was switched off. Every intake route now updates those counts as part of
  loading.
- **A load limit now means what it says.** Capping a run at N documents
  previously counted documents *examined*, including ones already loaded, so an
  incremental run against a mostly-loaded corpus could load nothing. It now
  counts documents actually loaded, and reports how many were left for a later
  run.
- Every document ingested from object storage or a remote reference records
  where it came from, so a corpus entry can be traced back to its origin.

## Action required

None. This release changes no database structure and no stored data.

Administrators who track bulk-load results should expect some outcomes
previously reported as "duplicate" to appear as failures. That reflects
documents which were already failed, not a new problem.
