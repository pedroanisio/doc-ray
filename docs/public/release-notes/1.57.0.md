# Doc-Ray 1.57.0

Corpus-wide counts are now current rather than up to ten minutes old, the
library keeps up while documents are being added, and a word-frequency figure
that could have been reported against an empty total is repaired.

## Who is affected

- **Anyone reading corpus-wide totals or word shares.** Totals used to lag
  behind by up to ten minutes during ingest and are now current as of the last
  change. If you are upgrading from 1.56.0 specifically, see *Action required* —
  one figure may have been wrong rather than merely stale.
- **Anyone adding or removing documents in bulk.** Adding documents no longer
  slows the whole library down while it catches up, and deleting one now
  correctly reduces the totals.
- **Administrators.** The database work behind this is the largest change in the
  release, and it removes a long-standing source of load.

## What changed

**Totals are kept up to date incrementally.** Every time a document changed, the
library recalculated its word statistics by re-reading the entire corpus, and it
did so repeatedly during ingest. Each document now records its own contribution,
and only the difference is applied to the totals. The result is the same numbers
for far less work, so counts stay current instead of being deliberately delayed
to make the cost bearable.

**Counts are no longer briefly stale by design.** The delay that existed only to
make the old recalculation affordable is gone.

**Deleting a document now updates the totals.** Previously the figures stayed as
they were until the next full recalculation; a deleted document's words are now
withdrawn immediately.

**A word's share is measured against a real total again.** In 1.56.0 the
corpus-wide word total was introduced but, on some installations, was never
actually written — the update that should have filled it in was silently
rejected by the database's access rules and still reported success. Where that
happened, the total read as zero, so any share calculated from it was
meaningless. The figure is now filled in through a path that cannot be silently
rejected, and it can be repaired again at any time without recalculating
anything else. Individual word counts were never affected — only the share.

## Action required

Administrators should apply the database migrations shipped with this release in
the usual way; they are additive and safe to apply while the service is running.

If you deployed 1.56.0 and use word-frequency lookups, check one term's reported
total. A total of zero means the figure was never filled in on your
installation; applying this release repairs it. Individual counts were always
correct, so nothing else needs re-checking.

Documents already in the library are unaffected and need no reprocessing.
