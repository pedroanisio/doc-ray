# Doc-Ray 1.53.0

Version 1.53.0 moves the curation tools to their own address, so agents that only
read stop paying for tools they never call.

## Who is affected

- **Anyone whose AI assistant connects to doc-ray for reading** — nothing to do.
  Your connection gets smaller and cheaper on its own.
- **Anyone whose assistant edits the corpus** — **action required**, see below.

## Action required

If your assistant uses doc-ray's editing tools — correcting entities, tagging
documents, managing collections, queueing reprocessing — **change its address**:

| | |
|---|---|
| Before | `https://doc-ray.com/mcp` |
| After | `https://doc-ray.com/mcp/curate` |

Reading tools are available at both addresses, so a curation assistant needs only
the second one. Assistants that only read keep using `https://doc-ray.com/mcp`
and need no change.

## Why

Every assistant downloads the full list of available tools before it can do
anything useful. Previously, switching on editing made that list grow for
*everyone* connecting to the main address — a reader loaded 65 tool descriptions
to use perhaps five. Editing tools now live at their own address, so the main one
carries the reading tools alone: about 42% less to load before the first useful
answer, which is both faster and cheaper on every session.

## What to know

- **Point each assistant at one address.** An assistant configured with both
  loads both lists and saves nothing. Give read-only assistants the main address
  and curation assistants the curation one.
- **The curation address is not less protected.** Both run behind the same
  sign-in, the same rate limits, and the same audit trail, and every edit is still
  checked against your permissions on the specific document. Reaching the address
  does not grant the right to change anything.
- **If editing is switched off for your deployment, the curation address does not
  exist at all** — it returns "not found" rather than an empty tool list.
