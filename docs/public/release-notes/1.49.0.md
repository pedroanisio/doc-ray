# Doc-Ray 1.49.0

Version 1.49.0 makes two things usable that previously existed but could not be
reached: adding a document by naming it, and finding out why one failed.

## Who is affected

- **Readers and researchers** — the upload page now accepts a reference beside
  the file picker. Paste an arXiv link and the server fetches the paper; you
  never download it yourself. Previously this worked only from a command line
  on the server.
- **Integrators** — `ingestDocument` takes either a `file` or a `ref`. Existing
  upload calls are unchanged.
- **Agents (MCP)** — a new `ingest_document` tool takes a reference. Because MCP
  carries no file uploads, this is the only way an agent can add a document to
  the corpus.
- **Anyone looking at a document that failed to ingest** — the reason is now on
  the page.

## What to know before relying on it

- **Give exactly one of a file or a reference.** Supplying both is rejected
  rather than resolved in favour of one; supplying neither says so.
- **A reference is checked immediately, fetched later.** A reference no source
  recognises is refused right away, so you learn about a typo at once instead of
  by polling a job that was always going to fail. A recognised reference is
  downloaded by the server in the background, so the request returns as soon as
  the work is queued — poll the returned job for the resulting document.
- **Supported references today are arXiv**: `abs` and `pdf` links,
  `arxiv:<id>`, bare ids, and old-style ids. Other origins need an adapter.
- **Titles**: a title you supply wins; otherwise the source's own title is used
  (arXiv's, for instance); otherwise the title read out of the file.
- **A failed document now shows why it failed**, most often that a scanned PDF
  carries no text layer and needs OCR. It also states plainly that re-ingesting
  the same file cannot help — documents are stored by content, so an identical
  copy is recognised as the one that already failed. Fix the file and ingest the
  corrected version.
- **The administration console's status filter now lists the statuses that
  exist.** It previously offered "ready" and "processing", which no document has
  ever been, so those filters silently returned nothing. Failed rows also show
  their reason.

## Action required

None. This release changes no database structure and no stored data.
