{# doc·ray icon system — one inline SVG sprite, one macro. Why inline and not an external sprite file: an icon here must take its colour from the surface it sits on (masthead ink, accent on the active nav item, status hues, the footer's own light ramp) and must flip with the light/dark theme. That is `currentColor`, and `currentColor` inside an *externally* referenced resolves against the referenced document rather than the referencing one, so an external sprite renders the wrong colour exactly where the theme matters. Inlining the sprite once per page costs a few kB before compression and makes every icon inherit colour correctly, style with the page's own CSS, and need zero extra requests. Why a sprite and not an icon font: a font ships four format files, renders glyphs through the text pipeline (so it inherits font smoothing and line-box quirks), and puts meaning in a private-use codepoint that degrades to a tofu box when the font fails to load. A either draws or does not exist. Geometry: a 24x24 grid, stroke-based, 1.75 stroke units, round caps/joins. Presentation attributes live on each so an icon still draws if it is ever referenced from a context that has not loaded the stylesheet. Every icon is decorative by default (aria-hidden) because it labels adjacent text. Pass `label` only where the icon is the control's *only* name. #} {% macro sprite() -%} {%- endmacro %} {# icon(name) — decorative by default; pass `label` when the icon is the only name the control has, which promotes it to role="img" with an accessible name. #} {% macro icon(name, label='', class_name='') -%} {%- endmacro %}
